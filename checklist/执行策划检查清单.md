# 执行策划检查清单

## 前置条件

在开始详细策划之前，确保以下条件已满足：

- [ ] 主策划已完成需求分析
- [ ] 主策划已完成模块拆解
- [ ] 主策划已完成游戏大纲
- [ ] 已明确模块/系统列表
- [ ] 已明确开发优先级
- [ ] 文档结构已创建

**注意**：需求分析、模块拆解、游戏大纲是主策划的职责，执行策划在此基础上进行详细策划。

## 详细策划阶段

### ⚠️ 核心约束

**执行策划绝对不能做的事情**：
- ❌ **严禁写代码**：不允许在文档中包含任何实现代码
- ❌ **严禁写函数/类定义**：如 `def calculate_damage()` 或 `class Player:`
- ❌ **严禁写伪代码**：如 `if (hp > 0) then return true`
- ❌ **严禁建议技术实现**：如"用Python的pygame库实现"
- ❌ **严禁定义数据结构**：如"数据库字段id, name, level"
- ❌ **严禁写API接口**：如`GET /api/user/{id}`

**执行策划应该做的事情**：
- ✅ 描述"做什么"（WHAT），而不是"怎么做"（HOW）
- ✅ 定义功能和需求
- ✅ 说明公式和参数（用数学表达式，不是代码）
- ✅ 描述交互流程
- ✅ 说明UI布局
- ✅ 规定数值范围

**错误示例**：
```markdown
❌ 错误：实现伤害计算
```python
def calculate_damage(attacker, defender):
    base = attacker.attack - defender.defense
    if base < 0:
        base = 0
    return base
```
```

**正确示例**：
```markdown
✅ 正确：伤害计算设计
## 伤害计算公式
基础伤害 = max(0, 攻击力 - 防御力)

当满足以下条件时触发暴击：
- 随机判定值（0-100）< 角色暴击率
- 暴击时伤害 × 2.0
```

**记住**：代码实现是程序员在Phase 4的职责！执行策划只负责设计。

- [ ] **确认**：我的文档中没有包含任何代码实现
- [ ] **确认**：我只描述了"做什么"，没有写"怎么做"
- [ ] **确认**：所有公式都用数学表达式，没有用代码

- [ ] 所有功能可实现（无超自然需求）
- [ ] 性能要求合理
- [ ] 开发时间可行
- [ ] 技术栈匹配团队能力

### 模块间接口

- [ ] 数据流向清晰
- [ ] 调用关系明确
- [ ] 依赖关系合理

## 技术可行性评估（推荐）

在正式移交程序员之前，建议先进行技术可行性评估：

### 评估流程

1. **临时切换到程序员角色**
   ```
   💻 切换到程序员角色，进行技术可行性评估...
   ```

2. **从技术角度审查所有设计文档**
   - [ ] 所有功能技术上可实现
   - [ ] 没有明显的技术瓶颈
   - [ ] 性能要求现实可达
   - [ ] 系统间依赖合理
   - [ ] 数据流清晰可实现

3. **评估结果处理**

   **如果一切可行**：
   - [ ] 输出："✅ 所有设计技术上可行"
   - [ ] 继续交付流程

   **如果发现问题**：
   - [ ] 切换回主策划角色讨论
   - [ ] 说明技术问题和限制
   - [ ] 讨论设计调整方案
   - [ ] 切换回执行策划更新文档
   - [ ] 重新评估

4. **切回执行策划角色**

### 评估收益

- ✅ 早期发现技术问题
- ✅ 避免后期返工
- ✅ 确保设计可实现
- ✅ 提高开发效率

**注意**：这个环节是可选的，但强烈推荐。如果是简单项目或有经验的团队，可以跳过。

## 交付给程序员的标准

执行策划可以交付的标准（必须全部满足）：

- ✅ **所有系统都有详细文档**

  - 文档命名符合规范
  - 文档在正确的模块文件夹下

- ✅ **文档中没有未完成内容**
  - 无TBD、待定、待讨论等标记

  - 无模糊的描述

- ✅ **程序员可以直接照着开发**
  - 功能描述清晰可执行
  - UI布局明确可绘制
  - 数值参数完整可配置
  - 技术要求清晰可验证
  - 系统间接口明确

- ✅ **已通过自动验证**
  - 运行 `scripts/test_design_doc.py` 全部通过
  - 无错误或警告

- ✅ **老板和主策划已确认**
  - 主策划已审阅
  - 老板已确认（如需要）
  - 收到开始开发的批准

## 执行策划注意事项

### 与主策划的协作
- ✅ 遵循主策划的模块划分和优先级
- ✅ 保持与主策划的术语一致
- ✅ 接口定义要与主策划协商
- ✅ 发现架构问题及时反馈给主策划

### 文档质量
- ✅ **详细**：程序员不需要额外询问
- ✅ **准确**：没有错误或矛盾
- ✅ **完整**：没有遗漏的功能点
- ✅ **可执行**：技术可实现

### 主动沟通
- ✅ 不确定的地方主动询问
- ✅ 不要假设或猜测
- ✅ 与老板确认设计细节
- ✅ 与主策划协调模块间接口
- ✅ 与程序员讨论可行性

### 常见错误
- ❌ 文档不够详细，程序员无法直接开发
- ❌ 遗漏异常情况和边缘情况

- ❌ 系统间接口不清晰
